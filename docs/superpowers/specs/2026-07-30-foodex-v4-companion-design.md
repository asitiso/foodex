# Foodex V4 캐릭터 동반자·무료 반응 엔진 설계

작성일: 2026-07-30  
상태: 구현 전 승인 설계

## 1. 목표

Foodex V4의 목표는 기능을 홈에 더 쌓는 것이 아니라 다음 세 가지 체감을 만드는 것이다.

1. 앱을 열면 AI 친구가 나를 기억하고 반응하는 느낌
2. 식사 기록 후 카드 획득이 게임처럼 느껴지는 손맛
3. API 비용 없이도 매일 다른 반응과 성장 결과를 제공하는 구조

대상 사용자는 식사 기록 자체를 귀찮아할 수 있는 아동을 포함한다. 사용자를 평가하거나 식사를 강요하지 않고, 사진 촬영과 카드 수집을 즐거운 행동으로 만든다.

## 2. 확정된 제품 방향

### 2.1 플랫폼

- 기존 React/Vite 웹앱을 유지한다.
- Android를 우선 지원한다.
- 웹 기능을 안정화한 뒤 Capacitor로 Android 앱을 패키징한다.
- 카메라, 햅틱, 앱 아이콘, 시작 화면, 알림은 Android 네이티브 기능과 연결한다.
- iOS는 같은 코드베이스를 이용한 후속 확장으로 둔다.

### 2.2 하단 내비게이션

하단 메뉴는 5개로 고정한다.

1. 홈
2. 도감
3. 촬영
4. 모험
5. AI 친구

촬영은 중앙의 가장 크고 눈에 띄는 원형 버튼으로 배치한다.

기존 놀이 탭은 제거하고 기능을 다음과 같이 재배치한다.

- 퓨전 연구소: 도감 내부
- 카드 꾸미기: 카드 상세 화면
- 퀘스트, 업적, 이벤트, 보물상자: 모험
- 응원, 식사 일기, 월간 리포트: AI 친구

## 3. 홈 화면

### 3.1 시각 방향

홈은 C안인 캐릭터 방 육성형으로 구현한다.

- 따뜻한 크림·코럴 계열 색상
- 화면 중심에 기본 AI 친구 캐릭터
- 배경은 성장하는 캐릭터 방
- 둥근 게임 UI와 장난감 같은 깊이감
- 평면 정보 카드보다 캐릭터와 공간을 우선
- 캐릭터의 표정, 작은 동작, 말풍선으로 상태 전달

### 3.2 홈 정보

홈에는 다음 다섯 항목만 둔다.

1. AI 캐릭터와 한 줄 반응
2. 플레이어 레벨
3. 오늘 획득한 카드
4. 오늘의 도전
5. 연속 기록

레벨, 오늘의 카드, 오늘의 도전, 연속 기록은 2×2 미니 상태 카드로 배치한다.

홈에서 제거하는 항목:

- 전체 퀘스트 목록
- 시즌 상세 진행률
- 보물상자 상세
- 이벤트 목록
- 전체 최근 카드
- 경험치 상세 수치

각 미니 상태 카드를 누르면 관련 상세 화면으로 이동한다.

### 3.3 캐릭터 방 성장

V4에서는 방 꾸미기를 사용자가 직접 편집하지 않는다. 달성 조건에 따라 장식이 자동 배치된다.

- 레벨 1: 기본 방
- 레벨 3: 작은 화분
- 레벨 5: 음식 포스터
- 레벨 8: 카드 진열대
- 레벨 10: 창문 배경
- 한식 세트 완성: 전통 조명
- 과일 세트 완성: 과일 쿠션
- 면류 세트 완성: 냄비 장식
- 시즌 완료: 한정 벽지

직접 방 꾸미기는 V5 범위로 둔다.

## 4. 무료 규칙형 동반자 엔진

### 4.1 원칙

V4 초기 버전은 외부 AI API를 호출하지 않는다.

- 사진을 실제로 분석하지 않으므로 `AI 사진 분석 완료`라고 표시하지 않는다.
- `푸드 친구가 카드를 만들고 있어요`처럼 사실에 맞는 게임 표현을 사용한다.
- 캐릭터는 저장된 사용자 기록을 바탕으로 상황에 맞는 반응을 선택한다.
- 사용자가 캐릭터를 지능적으로 느끼게 만드는 핵심은 허위 분석 문구가 아니라 기억, 맥락, 반복 방지다.

### 4.2 입력 컨텍스트

동반자 엔진은 반응을 만들기 전에 다음 값을 읽는다.

- 현재 시각과 식사 시간대
- 오늘 식사 횟수
- 마지막 식사 시각
- 최근 7일 음식 기록
- 신규 음식 여부
- 동일 음식 반복 횟수
- 카드 희귀도
- 플레이어 레벨과 다음 레벨 진행도
- 연속 기록 일수
- 일일 퀘스트 진행도
- 도감 및 세트 완성률
- 현재 계절과 이벤트
- 최근 사용한 대사와 표현
- 새 장식 또는 보상 획득 여부

### 4.3 사건 우선순위

한 번의 기록에서 여러 사건이 발생해도 가장 중요한 사건 하나를 주 반응으로 선택한다.

기본 우선순위 점수:

- 첫 발견 음식: 40
- 연속 기록 갱신: 30
- 일일 도전 완료: 50
- 오랜만에 기록한 카테고리: 25
- 동일 음식 3회 기록: 20
- 레벨업 또는 레벨업 임박: 30
- 세트 완성: 60
- 업적 달성: 60
- 에픽 카드: 60
- 전설 카드: 100
- 방 장식 획득: 55

동점이면 더 드문 사건을 먼저 선택한다. 나머지 사건은 작은 배지나 보상 요약으로 표시한다.

### 4.4 감정 상태

캐릭터는 다섯 가지 감정 상태를 가진다.

| 상태 | 조건 | 표현 |
|---|---|---|
| 평온 | 특별한 사건 없음 | 기본 표정과 호흡 동작 |
| 기대 | 촬영 전, 퀘스트 임박 | 몸 흔들기와 촬영 유도 |
| 기쁨 | 새 카드, 연속 기록 | 점프와 반짝임 |
| 놀람 | 희귀·에픽·전설 카드 | 확대, 놀란 표정 |
| 축하 | 레벨업, 업적, 세트 완성 | 전용 애니메이션 |

기록이 끊겼을 때 슬픔, 실망, 비난 표현은 사용하지 않는다. `오늘부터 새로운 모험을 시작하자`처럼 재시작을 환영한다.

## 5. 음식 선택 경험

### 5.1 기본 흐름

1. 사진 촬영
2. 음식 빠른 선택
3. 카드 생성 연출
4. 캐릭터 반응
5. 퀘스트와 방 성장 반영

### 5.2 빠른 선택

음식 선택 화면의 우선순위:

1. 같은 시간대에 자주 먹은 음식
2. 최근 기록한 음식
3. 즐겨찾기 음식
4. 시간대별 기본 추천
5. 음식 카테고리
6. 직접 입력

사용자는 가능한 한 한 번의 탭으로 음식 선택을 끝낸다.

### 5.3 음식 사전

초기 음식 사전은 약 100개로 구성한다. 각 음식은 다음 속성을 가진다.

- 표시 이름
- 별칭과 자동완성 키워드
- 상위 카테고리
- 지역
- 맛 속성
- 대표 색상
- 카드 속성
- 연관 퀘스트
- 사용할 수 있는 캐릭터 반응군

사전에 없는 음식은 입력값 그대로 저장하고 카테고리만 한 번 선택한다. 다음 기록부터 자동완성 후보로 노출한다.

## 6. 문장 합성

### 6.1 구조

대사는 다음 부품을 조합한다.

`상황 시작어 + 음식 표현 + 게임 반응`

예:

`오늘의 첫 발견이네! + 따뜻한 한 그릇이 + 도감에 새로운 빛을 켰어!`

화면별 최대 길이:

- 홈 말풍선: 약 15자
- 카드 공개 반응: 약 25자
- 식사 일기: 2~3문장
- 월간 리포트: 4~6문장

### 6.2 반복 방지

- 같은 완성 문장은 30일간 다시 사용하지 않는다.
- 같은 시작 표현은 최근 5회 동안 제외한다.
- 같은 감탄사는 연속 2회 사용하지 않는다.
- 같은 음식 수식어는 최근 3회 동안 제외한다.
- 특별 대사는 조건당 한 번만 사용한다.
- 계절 대사는 해당 계절에만 사용한다.

대사 선택 가중치:

- 미사용 대사: 3
- 오랫동안 미사용: 2
- 음식 속성과 일치: 2
- 현재 퀘스트와 연결: 2
- 최근 사용: 0

## 7. 카드 합성

### 7.1 카드 이름

기본 구조는 `속성어 + 음식명 + 칭호`다.

- 따뜻함: 포근한, 햇살, 온기
- 매운맛: 불꽃, 화염, 붉은
- 시원함: 얼음, 바람, 서리
- 달콤함: 꿀빛, 별사탕, 꿈결
- 건강함: 초록, 활력, 숲의

칭호 예:

- 기사
- 요정
- 탐험가
- 마법사
- 대장
- 수호자
- 달인

희귀도별 이름 규칙:

- 일반: 짧은 수식어 + 음식명
- 희귀: 속성어 + 음식명 + 칭호
- 에픽: 두 단계 수식어 + 음식명 + 칭호
- 전설: 사전에 등록된 고유 이름

### 7.2 카드 이미지

V4에서는 매 기록마다 AI 이미지를 생성하지 않는다.

- 음식 카테고리별 기본 일러스트를 사용한다.
- 속성 색상, 테두리, 장식, 등급 이펙트를 조합한다.
- 전설과 시즌 카드는 별도 제작한 고유 에셋을 사용한다.

이 방식은 생성 대기시간과 API 비용이 없고 카드 세계관의 일관성을 유지한다.

## 8. 식사 일기와 월간 리포트

### 8.1 식사 일기

하루 기록을 다음 순서로 합성한다.

1. 오늘 먹은 음식
2. 가장 중요한 게임 진행
3. 다음 기록을 기대하게 하는 문장

기록 수가 적다는 평가나 압박은 하지 않는다.

### 8.2 월간 리포트

다음 값을 데이터로 계산해 보여준다.

- 월간 기록 수
- 가장 자주 기록한 음식
- 신규 발견 음식
- 가장 많이 모은 카테고리
- 최고 연속 기록
- 희귀 카드 수
- 완성에 가까워진 도감
- 캐릭터와 방의 변화

건강 진단이나 영양 평가처럼 표현하지 않는다. 관찰과 발견 중심으로 작성한다.

## 9. 게임 연출

| 사건 | 화면 효과 | 음향·햅틱 |
|---|---|---|
| 일반 카드 | 작은 반짝임 | 짧은 팝음 |
| 희귀 카드 | 푸른 빛 확산 | 짧은 진동 1회 |
| 에픽 카드 | 화면 암전 후 등장 | 상승음과 진동 2회 |
| 전설 카드 | 전용 배경과 파티클 | 전용 팡파르 |
| 퀘스트 완료 | 체크 배너 | 성공음 |
| 레벨업 | 캐릭터 점프 | 팡파르와 강한 진동 |
| 방 장식 획득 | 장식 자동 배치 | 짧은 톡 소리 |

효과음은 10~15개로 제한한다. 설정에서 효과음, 배경음, 햅틱을 각각 끌 수 있게 한다. 지속 배경음은 기본 범위에서 제외하고 중요한 장면에만 짧은 음향을 사용한다.

## 10. 시스템 구조

```text
식사 기록
  → Context Builder
  → Priority Engine
  → Dialogue Composer
  → Card Composer
  → Reaction Director
  → Supabase 저장
```

모듈 책임:

- Context Builder: 사용자 상태를 한 객체로 정규화
- Priority Engine: 가장 중요한 사건과 부가 사건 선택
- Dialogue Composer: 반복되지 않는 상황 대사 생성
- Card Composer: 카드 이름과 설명 생성
- Reaction Director: 표정, 동작, 효과, 음향, 햅틱 결정
- Repository: 기록, 최근 대사, 캐릭터 상태, 방 장식 저장

나중에 유료 AI를 도입할 경우 Dialogue Composer와 Card Composer만 교체할 수 있게 인터페이스를 분리한다.

## 11. 오류 및 오프라인 처리

- 음식 사전 로딩 실패: 기본 카테고리와 직접 입력 제공
- 대사 후보 소진: 가장 오래 사용하지 않은 대사를 재사용
- 음향 재생 실패: 시각 효과와 햅틱만 실행
- 햅틱 미지원: 조용히 건너뜀
- Supabase 연결 실패: 로컬 저장 후 재연결 시 동기화
- 사진 저장 용량 초과: 사진 없이 기록 저장 선택 제공
- 사용자 입력 음식이 미분류: 기타 카테고리로 저장 후 다음 기록에서 재분류 가능

핵심 기록 흐름은 애니메이션, 음향 또는 네트워크 오류 때문에 중단되지 않는다.

## 12. 데이터 요구사항

기존 식사, 카드, 보상 데이터에 다음 개념을 추가한다.

- CompanionState
  - 감정 상태
  - 레벨
  - 마지막 반응
  - 획득 장식
- DialogueHistory
  - 대사 ID
  - 사용 시각
  - 발생 상황
- FoodPreference
  - 음식명
  - 사용 횟수
  - 시간대별 횟수
  - 마지막 사용 시각
  - 즐겨찾기 여부
- RoomUnlock
  - 장식 ID
  - 해금 조건
  - 해금 시각
- DailyJournal
  - 날짜
  - 합성 문장
  - 근거가 된 기록 ID

테이블과 RLS의 구체적 형태는 구현 계획에서 확정한다.

- 음식 사전: 약 100개
- 음식 속성: 12개

- 음식 표현: 100개
- 게임 반응: 60개
- 홈 대사: 80개
- 특수 상황 대사: 50개
- 카드 수식어: 120개

콘텐츠는 코드와 분리된 데이터 파일로 관리한다.

## 14. 검증 기준

### 단위 테스트

- 같은 컨텍스트에서 유효한 주 사건을 선택하는지
- 전설, 업적, 세트 완성 우선순위가 보존되는지
- 최근 사용 대사가 반복되지 않는지
- 음식 속성과 카드 이름이 맞게 연결되는지
- 기록이 끊겨도 부정적 대사가 생성되지 않는지
- 월간 리포트 수치가 원본 기록과 일치하는지

### 통합 테스트

- 촬영부터 카드 저장까지 네트워크 없이 완료되는지
- 저장 후 홈 상태와 캐릭터 반응이 갱신되는지
- 퀘스트 완료와 방 장식 해금이 중복 지급되지 않는지
- Supabase 동기화 후 대사 이력과 보상이 유지되는지

### 모바일 검증

- 작은 Android 화면에서 홈이 한 화면에 핵심 정보를 표시하는지
- 중앙 촬영 버튼을 한 손으로 누를 수 있는지
- 애니메이션 중에도 화면 전환과 저장이 가능한지
- 효과음과 햅틱을 각각 끌 수 있는지
- 저사양 기기에서 카드 공개 연출이 끊기지 않는지

4. 카드·대사 합성기와 반복 방지
