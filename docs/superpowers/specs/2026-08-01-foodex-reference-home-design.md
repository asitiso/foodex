# Foodex 레퍼런스형 홈 화면 설계

## 목표

Vercel의 최신 READY Preview 커밋 `7eb0798ceb96f0e81c07117d538f88f559c35216`을 기준으로 Foodex 홈 화면을 제공된 키즈 게임 레퍼런스와 같은 정보 구조와 분위기로 재구성한다. 기능, 라우팅, 데이터 구조는 유지하고 홈 화면의 DOM 구조, 배치, 스타일, 아이콘 표현만 교체한다.

## 사용자 효율 기준

- 홈의 핵심 행동인 도감, 모험, 식사 기록, 버디 진입을 한 화면에서 바로 찾게 한다.
- 기존 화면과 데이터 흐름을 재사용해 새 기능 학습이나 유지관리 비용을 만들지 않는다.
- 레퍼런스와 차이가 거의 없는 부분은 재작업하지 않고, 차이가 큰 랜드마크 수, 하단 내비게이션, 공간 배치를 우선 개선한다.

## 기준과 범위

- 기준 커밋: `7eb0798ceb96f0e81c07117d538f88f559c35216`
- 유지: 현재 클릭 핸들러, 화면 전환, 진행 데이터, 코인 데이터, 캐릭터 상태, 접근성 레이블
- 변경: 홈 전용 컴포넌트 계층, 홈 DOM 배치, 홈 전용 CSS, 홈 아이콘 표현
- 비범위: 신규 라우트, 신규 데이터 모델, 상점/소식 기능 추가, 다른 화면 디자인 개편

## 화면 구조

### 상단 HUD

- 왼쪽에는 레벨, 카드, 식사/연속일을 세로로 쌓은 상태 레일을 둔다.
- 중앙에는 흰색 볼륨 글자, 보라 스트로크, 분홍/보라 하단 그림자, 노란 별로 구성된 일체형 FOODEX 로고를 둔다.
- 오른쪽에는 코인 메달, 수량, 추가 기호를 포함한 캡슐형 코인 바를 둔다.
- 각 상태 카드와 코인 바는 기존 핸들러와 `aria-label`을 유지한다.

### 메인 월드

- 후면 중앙: 성 랜드마크와 `모험` 간판 버튼
- 왼쪽: 딸기 도감 건물과 `도감` 간판 버튼
- 전면 중앙: 카메라 오브젝트와 `식사 기록` 간판 버튼
- 오른쪽: 버디 집과 `버디` 간판 버튼
- 캐릭터는 중앙 광장 위에 크게 배치하되 식사 기록 버튼의 클릭 영역과 겹치지 않는다.
- 버튼은 독립 HUD처럼 떠 보이지 않도록 각 건물/오브젝트의 입구 또는 간판 위치에 결합한다.

### 하단 메뉴

- 홈 화면에서만 기존 5탭 하단 바를 렌더링하지 않는다. 다른 화면에서는 기존 하단 바를 유지한다.
- 홈 하단에는 업적, 퀘스트, 상점, 소식의 대형 카드 네 개를 한 줄로 둔다.
- 연결은 `업적 → 모험`, `퀘스트 → 모험`, `상점 → 도감`, `소식 → 버디`로 고정한다.
- 각 카드는 아이보리 내부, 두꺼운 보라 외곽선, 흰색 내부 하이라이트, 진한 하단 그림자와 장난감형 아이콘을 사용한다.

## 컴포넌트 경계

- `HomeScreen`: 기존 데이터를 현재 홈 월드 프롭으로 변환한다.
- `WorldHomeScene`: HUD, 네 랜드마크, 캐릭터, 하단 카드의 공간 배치만 담당한다.
- `GameHud`: 상태 레일, 로고, 코인 바를 담당한다.
- `WorldHotspot`: 건물 결합형 간판 버튼의 공통 상호작용과 접근성을 담당한다.
- `MealRecordOrb`: 중앙 카메라 오브젝트와 식사 기록 행동을 담당한다.
- `HomeMenuCard`: 하단 4카드의 공통 구조와 클릭 동작을 담당한다.
- `GameIcon`: 기존 아이콘 API를 재사용하고 필요한 3D 장난감형 표현만 추가한다.
- `homeGameUi.css`: 홈 전용 스타일을 격리하며 다른 화면의 크기와 배치에는 영향을 주지 않는다.

## 반응형 규칙

- 기준 뷰포트는 `375×667`, `390×844`, `430×932`이다.
- 홈은 `100dvh` 안에서 스크롤 없이 완성한다.
- 랜드마크 좌표는 월드 컨테이너를 기준으로 퍼센트 배치하고, 크기는 `clamp()`와 컨테이너 비율로 제한한다.
- 높이 667px에서는 HUD, 월드, 하단 카드의 세로 간격과 카드 높이를 압축하되 최소 44px 터치 영역은 유지한다.
- 높이가 늘어날수록 월드와 캐릭터를 확대하고 빈 공간을 늘리며, 하단 카드는 화면 아래 안전 영역 위에 고정한다.
- 하단 카드, 랜드마크 버튼, 캐릭터의 시각 영역과 클릭 영역은 서로 겹치지 않는다.

## 시각 언어

- 모든 카드와 버튼은 둥근 사각형, 두꺼운 보라 외곽선, 내부 흰색 하이라이트, 아래쪽 진한 입체 그림자를 공유한다.
- 일반 웹앱의 평면 버튼, 얇은 테두리, 회색 아이콘은 사용하지 않는다.
- 배경과 오브젝트는 밝은 하늘, 크림색 석재, 분홍/보라 지붕, 초록 정원 팔레트를 공유한다.
- 애니메이션은 기존 `reducedMotion`과 `prefers-reduced-motion` 설정을 따른다.

## 데이터와 오류 처리

- 데이터 계산과 저장 로직은 변경하지 않는다.
- 상태 값이 0이어도 레이아웃이 줄어들지 않게 고정된 HUD 슬롯에 표시한다.
- 기존 동기화 상태와 계정 보호 UI는 홈 월드의 한 화면 배치를 깨지 않도록 홈에서 비차단 오버레이 또는 기존 조건부 흐름을 유지한다.

## 테스트와 검증

1. 홈 구조, 클릭 매핑, `aria-label`, 홈에서의 5탭 숨김을 테스트로 먼저 실패시킨다.
2. 최소 구현 후 집중 테스트를 통과시킨다.
3. 각 주요 구조 변경마다 전체 테스트와 `npm run build`를 실행한다.
4. Preview를 배포한다.
5. `375×667`, `390×844`, `430×932` 스크린샷을 생성한다.
6. 레퍼런스와 비교해 가장 큰 차이가 남은 구조를 먼저 수정한다.
7. 로고/HUD, 랜드마크 4개, 캐릭터, 하단 4카드가 모두 겹침 없이 한 화면에 보일 때 완료한다.

## 성공 기준

- 세 검증 크기 모두 세로 스크롤이 없다.
- 상단 HUD, 4개 랜드마크, 중앙 캐릭터, 하단 4카드가 모두 한 화면에 존재한다.
- 홈의 기존 5탭 하단 바는 보이지 않고 다른 화면에서는 유지된다.
- 모든 홈 행동이 승인된 기존 화면으로 이동한다.
- 레퍼런스와 마찬가지로 첫인상이 일반 웹앱이 아니라 키즈 게임 월드로 읽힌다.
