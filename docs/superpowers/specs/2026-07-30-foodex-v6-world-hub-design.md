# Foodex V6 음식 세계관 허브 설계

작성일: 2026-07-30
상태: 구현 전 승인 설계

## 1. 목표

Foodex V6의 목표는 식사 기록 앱에 기능을 더 붙이는 것이 아니라, 사용자가 모은 음식 카드들이 하나의 세계 안에서 살아 움직이는 느낌을 만드는 것이다.

V6.0은 “음식 세계관 허브”를 첫 번째 큰 업데이트로 제공한다. 사용자는 홈에서 바로 음식 세계로 들어가고, 자신이 발견한 음식 캐릭터, 음식 마을, NPC 셰프, 박물관 전시실, 오늘의 세계 이벤트를 한 화면 흐름 안에서 확인한다.

V6.0은 다음을 제공한다.

- 음식 세계관 허브
- 음식 마을
- 음식 캐릭터 주민
- NPC 셰프
- 음식 박물관 전시실
- 오늘의 세계 이벤트
- 음식별 관계와 작은 스토리의 기반 데이터

V6.0에서 제외하는 것은 다음과 같다.

- 자유 채팅형 AI
- 친구 교환과 가족 도감
- GPS, QR, 오프라인 이벤트
- AI 이미지 생성
- AI 영상, 숏폼, 다큐멘터리
- 대규모 실시간 운영 도구

이 제외 범위는 기능 가치가 낮아서가 아니라, V6.0에서 함께 넣으면 사용자가 무엇을 해야 하는지 흐려지고 관리 비용이 커지기 때문이다.

## 2. 제품 원칙

1. 사용자는 앱을 열자마자 “오늘 무엇을 하면 좋은지” 알 수 있어야 한다.
2. 음식 세계관은 새 기록 행동을 더 편하게 만들어야 하며, 별도 관리 작업을 늘리면 안 된다.
3. V6.0은 기존 V5.2의 “오늘의 모험 보드”와 연결되어야 한다.
4. 음식 캐릭터와 마을은 사용자가 이미 모은 카드에서 자동으로 생성된다.
5. 같은 정보를 홈, 도감, 모험, 세계관 허브에 중복 배치하지 않는다.
6. 건강 평가, 식단 압박, 실패 표현은 사용하지 않는다.
7. 게임 데이터는 우선 TypeScript 콘텐츠 카탈로그와 순수 함수로 관리한다.
8. Supabase 스키마 확장은 V6.0 첫 구현에서 필수로 하지 않는다.

## 3. 사용자가 느끼는 변화

V5.2까지는 사용자가 기록하면 카드와 퀘스트 결과가 보인다. V6.0에서는 그 카드들이 세계 안에 배치된다.

예시 흐름:

```text
홈
  → 오늘의 모험 보드
  → 음식 세계 입장
  → 라면 마을에 새 주민 등장
  → 라면 기사와 밥방패가 이웃이 됨
  → NPC 셰프가 오늘의 세계 이벤트 제안
```

이 변화는 기존 방식보다 편하다. 사용자는 도감, 퀘스트, 진화, 이벤트를 따로 해석하지 않고 “음식 세계에서 오늘 할 일”로 이해한다.

## 4. 정보 구조

하단 내비게이션은 기존 5개 구조를 유지한다.

1. 홈
2. 도감
3. 촬영
4. 모험
5. AI 친구

V6.0은 새 하단 탭을 추가하지 않는다. 대신 홈 안에 “음식 세계 입장” 버튼을 두고, 모험 화면 안에 세계관 탭을 추가한다.

### 홈

홈에는 다음을 추가한다.

- 음식 세계 입장 버튼
- 오늘의 세계 이벤트 한 줄
- 가장 활발한 음식 마을 한 줄

홈에 상세 세계 지도나 긴 스토리는 넣지 않는다. 홈이 무거워지면 기록 시작이 불편해지기 때문이다.

### 모험

모험 화면은 기존 오늘, 업적, 이벤트 탭에 “세계” 탭을 추가한다.

세계 탭 구성:

- 음식 세계 허브 요약
- 음식 마을 목록
- 오늘의 NPC 셰프 미션
- 최근 생긴 음식 관계
- 박물관 전시실 바로가기

### 도감

도감은 기존 카드, 세계지도, 세트, 퓨전 흐름을 유지한다.

V6.0에서는 도감 카드 상세에 다음 정보를 추가한다.

- 음식 캐릭터 칭호
- 사는 마을
- 관계 1~3개
- 짧은 스토리 문장
- 다음 만남 조건

## 5. V6.0 핵심 개념

### 5.1 음식 세계 허브

음식 세계 허브는 사용자가 모은 음식 콘텐츠를 한 화면에서 세계관으로 번역해 보여주는 요약 화면이다.

표시 항목:

- 세계 이름: 오늘의 식탁 왕국
- 발견한 마을 수
- 전체 주민 수
- 오늘 활동한 주민
- 진행 중인 세계 이벤트
- 다음 추천 기록

예시:

```text
오늘의 식탁 왕국
마을 3개 발견
주민 12명
오늘은 라면 마을이 활기차요
다음 목표: 면 음식 1번 더 기록하기
```

### 5.2 음식 마을

마을은 기존 지역, 세트, 음식 종류를 조합해 만든다. 새 저장소 없이 기존 카드 기록으로 계산한다.

초기 마을:

- 분식 마을: 라면, 밥, 간식
- 햇살 과일숲: 과일, 음료
- 든든한 밥상마을: 밥, 반찬, 만두
- 빵구름 언덕: 빵, 음료
- 세계 음식 거리: 초밥, 파스타, 기타

각 마을은 다음 값을 가진다.

- 발견 주민 수
- 대표 주민
- 마을 레벨
- 다음 개방 조건
- 완료 보상 문구

마을 레벨은 복잡한 별도 XP를 만들지 않고, 해당 마을 음식 카드 수와 고유 음식 수로 계산한다.

### 5.3 음식 캐릭터 주민

음식 캐릭터는 기존 음식 카드에서 파생한다.

예시:

- 라면 기사
- 밥방패 수호자
- 딸기 요정
- 피자 왕
- 초밥 닌자
- 파스타 마법사

각 주민은 다음 정보를 가진다.

- 이름
- 마을
- 성격 태그
- 현재 단계
- 기록 횟수
- 다음 성장 조건
- 대표 대사

캐릭터 성장은 기존 `FoodEvolution`을 재사용한다. 별도의 캐릭터 레벨 시스템을 만들지 않는다.

### 5.4 NPC 셰프

NPC 셰프는 매일 하나의 간단한 세계 미션을 제안한다.

초기 NPC:

- 마을 안내 셰프
- 계절 셰프
- 박물관 큐레이터 셰프

미션 예시:

```text
분식 마을이 북적이게 라면이나 밥을 기록해 봐!
보상: 분식 마을 친밀도 +1
```

보상은 실제 화폐나 새 저장소가 아니라 기존 진행도와 연결되는 문구, 전시실 진척, 장식 해금 조건으로 제한한다.

### 5.5 음식 박물관 전시실

박물관은 기존 도감을 더 이해하기 쉬운 전시실 구조로 보여준다.

초기 전시실:

- 면 전시실
- 밥상 전시실
- 과일 전시실
- 간식 전시실
- 세계 음식 전시실

각 전시실은 다음을 표시한다.

- 전시된 음식 수
- 필요한 음식 수
- 대표 카드
- 완성 보상

이 방식은 “전체 도감 11개 중 3개”보다 사용자가 훨씬 쉽게 다음 목표를 이해할 수 있다.

### 5.6 음식 관계

관계는 V6.0에서 작은 기반만 만든다. 관계 그래프나 소셜 기능은 만들지 않는다.

초기 관계 규칙:

- 같은 마을 음식이 함께 있으면 이웃
- 같은 날 기록된 음식은 오늘의 친구
- 세트 조건에 함께 들어간 음식은 모험 동료
- 퓨전 조합이 있는 음식은 연구 파트너

표시 예시:

```text
라면 기사와 밥방패가 분식 마을 이웃이 되었어요.
과일 요정과 음료 물결이 햇살 한입단을 준비 중이에요.
```

## 7. 데이터 설계

V6.0의 기본 구현은 기존 식사 기록, 카드, 보상 데이터에서 파생한다.

새 영구 저장이 필요한 항목은 만들지 않는다.

파생 데이터:

- `WorldHubProgress`
- `FoodVillageProgress`
- `FoodResident`
- `MuseumRoomProgress`
- `WorldEvent`
- `FoodRelationship`

이 값들은 모두 순수 함수에서 계산한다.

향후 V6.5 이후, 사용자가 직접 세계 이름을 바꾸거나 마을 장식을 편집하게 되면 그때 Supabase 테이블을 추가한다.

## 8. UI 방향

V6.0은 랜딩 페이지가 아니라 실제 사용 화면이어야 한다.

세계 허브는 다음 느낌을 가진다.

- 상단: 오늘의 식탁 왕국 요약
- 중앙: 음식 마을 카드 목록
- 하단: NPC 셰프 미션과 박물관 전시실

카드는 8px 안팎의 절제된 반경을 사용한다. 게임 UI이지만 정보 탐색 화면이므로, 장식보다 스캔하기 쉬운 구조를 우선한다.

모바일에서는 한 손 조작이 쉬워야 한다. 기록 버튼으로 돌아가는 경로는 항상 명확해야 한다.

## 9. 오류 처리

- 음식 카드가 없으면 세계 허브는 빈 화면 대신 첫 마을 개방 목표를 보여준다.
- 알 수 없는 음식 타입은 세계 음식 거리 또는 기타 주민으로 표시한다.
- 콘텐츠 정의에 없는 마을 ID는 앱을 깨뜨리지 않고 기본 마을로 묶는다.
- 관계가 없으면 관계 영역을 숨기고 “새 음식을 기록하면 관계가 생겨요”를 표시한다.
- 세계 이벤트가 없으면 NPC 셰프가 기본 기록 미션을 제안한다.

## 10. 테스트 기준

### 단위 테스트

- 음식 카드 기록으로 마을 주민 수가 계산된다.
- 같은 음식 반복 기록은 주민 수를 부풀리지 않는다.
- 같은 마을 음식은 이웃 관계를 만든다.
- 같은 날 기록된 음식은 오늘의 친구 관계를 만든다.
- 박물관 전시실 완성률이 고유 음식 기준으로 계산된다.
- 음식 카드가 없어도 기본 세계 허브 데이터가 만들어진다.

### 화면 테스트

- 홈에 음식 세계 입장 버튼이 보인다.
- 모험 화면의 세계 탭에서 마을, NPC 미션, 박물관 전시실을 볼 수 있다.
- 카드가 없는 사용자는 첫 기록 목표를 볼 수 있다.
- 라면과 밥을 가진 사용자는 분식 마을과 관계 문장을 볼 수 있다.
- 모바일 폭에서 텍스트가 버튼과 카드 밖으로 넘치지 않는다.

### 배포 검증

- `npm run test:run`
- `npm run build`
- Vercel Preview 배포 확인
- 모바일 브라우저에서 홈 → 세계 → 기록으로 돌아오는 흐름 확인

## 11. 완료 기준

1. 사용자가 홈에서 음식 세계로 들어갈 수 있다.
2. 세계 허브가 기존 카드 기록만으로 마을, 주민, 이벤트, 박물관을 보여준다.
3. 음식 마을은 고유 음식과 반복 기록을 구분한다.
4. 음식 관계는 최소 2종 이상 자동 생성된다.
5. NPC 셰프는 매일 하나의 기록 목표를 제안한다.
6. 도감과 모험 화면은 기존 기능을 잃지 않는다.
7. 새 Supabase 테이블 없이 기존 저장 구조로 동작한다.
8. 테스트와 빌드가 통과한다.

## 13. 구현 순서 제안

1. V6 콘텐츠 카탈로그와 진행도 계산
2. 음식 세계 허브 화면
3. 홈의 음식 세계 입장 버튼
4. 모험 화면 세계 탭
5. 박물관 전시실 요약
6. 음식 관계 문장
7. 테스트와 Vercel Preview 검증

이 순서가 기존 방식보다 편한 이유는 사용자가 처음부터 새 시스템을 배워야 하지 않기 때문이다. 홈의 버튼 하나로 시작하고, 기록할수록 세계가 자동으로 채워진다. 개발 측면에서도 기존 기록과 카드 데이터를 그대로 사용하므로 Supabase 마이그레이션 부담이 없다.
