# Foodex 음식 세계 홈·내 방 개편 설계

## 1. 목적

Foodex의 홈을 정보 카드가 쌓인 대시보드에서 상용 캐주얼 게임의 로비로 바꾼다. 사용자가 앱을 열었을 때 수치를 읽기 전에 선택한 푸디와 음식 세계를 보고, 한 번의 터치로 식사를 기록하게 만드는 것이 핵심이다.

기본 경험은 다음 한 줄로 고정한다.

> 음식 세계에 입장한다 → 푸디를 만난다 → 한 끼를 기록한다 → 보상을 받는다 → 내 방에서 성장 결과를 확인한다.

## 2. 확정된 아트 방향

- **홈:** 밝고 살아 있는 야외 음식 세계
- **내 방:** 따뜻하고 촉감 있는 캐릭터 방
- **특별 연출:** 카드 획득·진화·전직 순간에만 짧은 네온·빛 효과

홈과 내 방은 서로 다른 장소지만 동일한 캐릭터 렌더링, 외곽선, 버튼 재질, 아이콘 비율과 타이포그래피를 사용한다. 따라서 화면이 바뀌어도 하나의 게임으로 느껴져야 한다.

## 3. 범위

### 포함

- 홈 화면의 전체 시각 계층과 레이아웃 교체
- 내 방 화면의 전체 시각 계층과 레이아웃 교체
- 기존 레벨·카드·식사·코인·캐릭터·상점 데이터를 새 화면에 연결
- 선택한 푸디 4종의 홈·내 방 표시
- 캐릭터 클릭 반응과 배경 소품 상호작용
- 홈에서 내 방 및 식사 기록으로 가는 짧은 동선
- 공통 게임형 버튼·배지·하단 내비게이션 스타일
- 반응형·접근성·모션 감소 대응

### 제외

- 새로운 게임 규칙, 보상 경제 또는 Supabase 스키마 추가
- 현재 기록·도감·모험·상점 데이터의 재설계
- 모든 화면을 한 번에 새 일러스트로 교체
- 실시간 3D 렌더링이나 게임 엔진 도입
- 긴 대화형 AI 기능

이번 작업은 기능 추가보다 표현 계층을 바꾸는 작업이다. 기존 데이터와 흐름을 재사용해 사용 단계와 유지관리 비용을 늘리지 않는다.

## 4. 홈 화면

### 4.1 첫 화면 구성

모바일 세로 화면 한 장 안에 다음 요소만 노출한다.

1. 상단 중앙 `FOODEX` 로고
2. 상단 우측 코인 잔액
3. 좌측 상태 배지 3개
4. 중앙의 선택 캐릭터
5. 하단 중앙의 대형 식사 기록 버튼
6. 하단 내비게이션

스크롤 없이 핵심 행동을 완료할 수 있어야 한다. 기존 상태 카드, 식사 게이지, 모험 보드, 다음 목표 카드의 내용을 홈 아래로 길게 나열하지 않는다.

### 4.2 상태 배지

상태 배지는 최대 3개다.

- **레벨:** 별 아이콘, 현재 레벨, 짧은 XP 막대
- **오늘의 카드:** 오늘 획득한 카드 수
- **식사 진행:** 오늘 기록한 끼니 수와 연속 기록 불꽃

각 배지는 최소 높이 60px, 최소 본문 16px, 핵심 수치 20px 이상으로 만든다. 단순 표시가 아니라 버튼으로 동작한다.

- 레벨 배지 → 성장 요약 바텀시트
- 카드 배지 → 도감의 음식 수집 앨범
- 식사 배지 → 오늘의 식사 던전 요약

연속 기록은 별도 네 번째 카드로 만들지 않고 식사 배지에 작은 불꽃과 일수로 통합한다.

### 4.3 캐릭터

선택된 푸디가 화면 높이의 약 40~48%를 차지한다. 캐릭터는 배경 위에 독립 레이어로 배치해 4종 선택 상태를 그대로 반영한다.

기본 모션:

- 느린 호흡
- 자연스러운 눈 깜빡임
- 장식 또는 귀의 미세 움직임
- 과하지 않은 상하 바운스

클릭 반응:

- 점프
- 좌우 흔들기
- 귀 또는 장식 반응
- 한 바퀴 회전
- 표정 변화
- 별 팝

같은 반응이 연속으로 나오지 않도록 기존 중복 방지 큐를 재사용한다. `prefers-reduced-motion`에서는 위치 이동과 회전을 줄이고 표정·빛 변화만 남긴다.

캐릭터를 길게 누르거나 보조 버튼을 누르면 내 방으로 이동한다. 일반 클릭은 캐릭터 반응만 실행해 실수로 화면이 바뀌지 않게 한다.

### 4.4 식사 기록 버튼

카메라 버튼은 화면에서 가장 강한 CTA다.

- 최소 88px 원형 터치 영역
- 코랄 또는 상황별 강조색
- 흰색 식판·카메라 혼합 아이콘
- 두꺼운 외곽선과 짧은 그림자
- 누를 때 눌림, 복원, 작은 별가루

텍스트 설명을 항상 붙이지 않는다. 첫 방문이나 접근성 모드에서는 `식사 기록하기` 레이블을 노출하고, 이후에는 명확한 접근성 이름을 유지한 채 아이콘 중심으로 표시한다.

버튼은 현재의 기록 흐름을 그대로 연다. 추가 중간 화면을 만들지 않는다.

### 4.5 야외 음식 세계

배경은 UI와 캐릭터가 없는 독립 배경판으로 제작한다. 중앙 캐릭터 안전 영역과 좌측 배지 안전 영역을 비워 둔다.

기본 장면:

- 흐르는 음식 마을의 강
- 빵·채소·과일에서 착안한 작은 건물
- 멀리 보이는 음식 산
- 식물과 작은 길
- 밝은 아침 또는 낮의 자연광

상태 변화는 전체 배경을 매번 새로 생성하지 않고 가벼운 오버레이로 표현한다.

- 아침·점심·저녁: 조명과 하늘 톤
- 계절: 전경 식물·눈·낙엽 레이어
- 3끼 완료: 깃발·반짝임·축제 장식
- 지역 해금: 멀리 보이는 대표 건물 교체

초기 구현은 기본 배경 1개와 시간대 오버레이부터 시작한다. 계절·지역 변형은 같은 구조에 자산만 추가할 수 있어야 한다.

### 4.6 배경 상호작용

배경 소품은 2~3개만 클릭 가능하게 한다.

- 음식 집 → 현재 해금 지역 힌트
- 작은 배 또는 길 → 모험 화면
- 반짝이는 식물 → 하루 한 번 짧은 반응

상호작용은 새 경제 시스템을 만들지 않는다. 기존 화면으로 이동하거나 짧은 캐릭터 반응을 제공하는 수준으로 제한한다.

## 5. 내 방 화면

### 5.1 목적

내 방은 데이터 목록이 아니라 캐릭터와 획득 결과를 확인하는 장소다. 꾸미기, 캐릭터 선택, 성장, 변신, 전직, 코인 상점을 하나의 방 장면에서 찾을 수 있어야 한다.

### 5.2 구성

1. 상단: `내 방`, 코인 잔액, 닫기 또는 홈 이동
2. 중앙: 선택 캐릭터
3. 배경: 창문, 선반, 러그, 식물, 트로피, 가구
4. 하단 또는 측면: 3개의 큰 장소 버튼
   - 옷장: 캐릭터·스킨·장식
   - 성장 거울: 성장·변신·전직
   - 상점: 꾸미기 상품

기존 상점의 모든 상품을 방에 직접 펼치지 않는다. 장소를 누르면 한 개의 바텀시트가 열리며 현재 기능을 재사용한다.

### 5.3 꾸미기 미리보기

상품을 선택하면 구매 전에 방 안의 해당 위치에 반투명 미리보기를 표시한다.

- 구매 전: 반투명, 별 테두리
- 구매 가능: 가격과 `방에 놓기`
- 코인 부족: 부족한 코인 수와 다음 획득 방법
- 보유 중: `사용 중` 또는 `배치하기`
- 오프라인: 현재 저장 상태와 온라인 구매 필요 안내

구매 성공 후 목록보다 방 장면의 변화가 먼저 보이고, 이어서 짧은 축하 효과를 표시한다.

### 5.4 캐릭터 성장

캐릭터를 누르면 큰 캐릭터 상세 시트가 열린다.

- 현재 캐릭터와 성장 단계
- 다음 성장까지 남은 식사 행동
- 현재 직업과 대표 스킬
- 캐릭터 변경

긴 업적·통계 목록은 이 시트에 넣지 않는다. 상세 성장 화면으로 이동하는 한 개의 버튼만 둔다.

## 6. 공통 디자인 시스템

### 6.1 색상

홈:

- 하늘 파랑
- 식물 초록
- 보상 금색
- CTA 코랄

내 방:

- 크림
- 따뜻한 나무색
- 코랄
- 금색
- 민트 포인트

공통 텍스트는 짙은 자주색을 사용해 기존 Foodex 정체성과 대비를 유지한다. 기본 브라우저 파란 포커스 색은 사용하지 않는다.

### 6.2 형태와 재질

- 주요 버튼 모서리 20~28px
- 상태 배지 3~5px 외곽선
- 짧고 명확한 아래 그림자
- 유광 플라스틱, 부드러운 점토, 천 재질을 연상시키는 명암
- 아이콘마다 동일한 광원 방향과 외곽선 굵기

평면 카드에 테두리만 두르는 기존 표현은 제거한다. 모든 입체감은 공통 토큰과 클래스로 관리해 화면별 임의 스타일을 만들지 않는다.

### 6.3 글자와 터치 크기

- 일반 본문 최소 16px
- 상태 이름 14~16px
- 핵심 수치 20~24px
- 주요 버튼 레이블 18px 이상
- 터치 영역 최소 52×52px
- 카메라 CTA 최소 88×88px

작은 설명이 필요한 경우 화면에 상시 두지 않고 바텀시트 또는 툴팁으로 이동한다.

### 6.4 공통 모션

- 일반 버튼: 100~140ms 눌림
- 상태 배지: 160ms 튀어 오름
- 캐릭터: 400~700ms 반응
- 카드·변신 특별 연출: 최대 2.5초
- 모든 연출은 중간 탭으로 건너뛸 수 있어야 함

## 7. 자산 전략

상용 게임에 가까운 품질을 위해 배경과 캐릭터는 HTML 도형만으로 만들지 않는다.

필요 자산:

- 야외 음식 세계 배경판
- 따뜻한 내 방 배경판
- 푸디 4종의 투명 캐릭터 기본 렌더
- 공통 상태 배지 아이콘
- 하단 내비게이션 아이콘
- 시간대·축제용 가벼운 오버레이

배경은 WebP를 기본으로 하며 모바일 기준 적절한 해상도와 품질로 압축한다. 캐릭터는 투명 WebP 또는 PNG로 관리한다. 성장·직업 차이는 캐릭터 전체 이미지를 계속 추가하기보다 기존 장식 레이어와 색상 효과를 우선 재사용한다.

장면과 UI를 한 장의 이미지로 합치지 않는다. 그래야 캐릭터 선택, 수치 변경, 클릭 반응과 반응형 배치를 유지할 수 있다.

## 8. 컴포넌트 경계

제안 컴포넌트:

- `WorldHomeScene`: 홈 장면과 안전 영역
- `GameHud`: 로고·코인·상태 배지
- `HeroCompanion`: 선택 캐릭터와 반응
- `MealRecordOrb`: 식사 기록 CTA
- `WorldHotspot`: 배경 소품 상호작용
- `CompanionRoomScene`: 내 방 장면
- `RoomHotspot`: 옷장·성장·상점 진입
- `GameSheet`: 상태·상점·성장용 공통 바텀시트

도메인 계산과 저장 로직은 기존 모듈을 유지한다. 새 컴포넌트는 계산 결과를 props로 받고, 사용자의 행동을 콜백으로 전달한다.

## 9. 데이터와 오류 처리

Supabase 스키마는 변경하지 않는다.

- 레벨·카드·식사 진행·코인: 기존 조회 결과 사용
- 캐릭터 선택·성장·직업: 기존 진행 상태 사용
- 상점 구매: 기존 보안 RPC 사용
- 오프라인: 기존 IndexedDB 상태 표시

데이터 로드 실패 시 빈 숫자나 깨진 장면을 보여주지 않는다.

- 배지는 마지막 로컬 값 또는 `—` 표시
- 캐릭터는 기본 선택 캐릭터 표시
- 배경은 항상 로컬 정적 자산으로 렌더
- 저장 실패는 화면 전체 배너가 아니라 행동과 가까운 시트에서 재시도 제공

## 10. 성능 기준

- 첫 화면의 핵심 배경·선택 캐릭터·HUD만 우선 로드
- 내 방 자산은 진입 직전 또는 유휴 시간에 지연 로드
- 작은 화면에 불필요한 초고해상도 이미지를 전송하지 않음
- 배경과 캐릭터에 `srcset` 또는 동등한 반응형 자산 전략 적용
- 동시에 실행하는 장식 애니메이션 수 제한
- 저사양 기기와 데이터 절약 모드에서는 정적 배경과 축소 모션 사용

목표는 기존 홈보다 초기 상호작용 가능 시간이 유의미하게 나빠지지 않는 것이다.

## 11. 접근성

- 모든 아이콘 버튼에 명확한 한글 접근성 이름 제공
- 색상 외에도 아이콘·텍스트로 상태 구분
- 포커스는 Foodex 보라색과 금색의 두꺼운 링 사용
- 배경과 글자 대비 확보
- 모션 감소 설정 적용
- 캐릭터 반응은 진행에 필수인 정보가 아님
- 바텀시트는 키보드·스크린리더로 닫을 수 있음

## 12. 테스트 전략

### 컴포넌트 테스트

- HUD가 정확히 3개 상태 배지만 표시
- 배지 클릭이 올바른 시트 또는 화면을 엶
- 카메라 CTA가 기존 기록 흐름을 엶
- 선택 캐릭터가 홈과 내 방에 동일하게 표시
- 상점 미리보기·구매·코인 부족·오프라인 상태
- 캐릭터 클릭 반응 중복 방지
- 모션 감소 설정

### 통합 테스트

- 홈 → 식사 기록 → 통합 보상 → 홈 복귀
- 홈 캐릭터 → 내 방 → 상점 → 구매 → 방 변화
- 홈 배지 → 도감·식사 던전·성장 요약

### 시각 검증

- 360px, 390px, 430px 모바일 너비
- 작은 높이와 화면 확대 200%
- 주요 Android·iOS 브라우저
- 캐릭터 4종과 긴 수치
- 로딩·오프라인·저장 오류 상태

## 13. 구현 순서

1. 공통 게임 UI 토큰과 큰 터치 규칙
2. 야외 음식 세계 배경·캐릭터 자산 분리
3. 홈 장면과 3개 HUD 배지
4. 식사 기록 CTA 및 기존 흐름 연결
5. 홈 바텀시트와 배경 핫스팟
6. 내 방 장면과 3개 장소 핫스팟
7. 기존 상점·성장·캐릭터 선택 연결
8. 모션·접근성·성능 최적화
9. 전체 테스트와 실제 모바일 시각 검증

## 14. 완료 기준

- 홈 첫 화면에 대시보드형 정보 카드가 남지 않는다.
- 스크롤 없이 캐릭터와 식사 기록 CTA가 보인다.
- 상시 노출 상태는 코인과 3개 배지로 제한된다.
- 선택한 캐릭터가 홈과 내 방에 일관되게 표시된다.
- 홈과 내 방의 아트 방향은 다르지만 동일한 게임 UI 규칙을 사용한다.
- 기존 식사 기록·보상·도감·성장·상점 기능을 잃지 않는다.
- 185개 기존 테스트를 포함한 전체 테스트와 프로덕션 빌드가 통과한다.
- 주요 모바일 화면에서 터치 크기·글자 크기·대비 기준을 만족한다.
