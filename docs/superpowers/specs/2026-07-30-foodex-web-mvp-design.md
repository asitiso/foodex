# Foodex 웹 MVP 설계

## 1. 목적

Foodex는 칼로리 계산 앱이 아니라, 식사 사진을 찍고 카드를 수집하는 재미를 통해 식사 기록을 지속하게 만드는 모바일 우선 웹앱이다.

첫 사용자는 식사량이 적은 아이이며 직접 사진을 촬영한다. 앱은 먹은 양을 평가하거나 꾸짖지 않는다. 새로운 음식을 맛본 행동과 기록 자체를 긍정적으로 보상한다.

첫 MVP의 검증 목표는 다음 두 가지다.

1. 아이가 설명 없이 `사진 → 음식 선택 → 식사량 선택 → 카드 획득`을 완료할 수 있다.
2. 다음 카드가 궁금해 다시 식사를 기록하고 싶어 한다.

## 2. MVP 범위

### 포함

- 모바일 카메라 촬영 및 갤러리 이미지 선택
- 음식 종류 직접 선택
- 식사량 한 번 선택
- 카드 생성 및 공개 연출
- 카드와 식사 사진의 기기 내 저장
- 홈, 기록, 도감 화면
- 발견 음식 수, 경험치, 마지막 식사 시간 표시

### 제외

- 실제 AI 음식 인식
- Firebase, 로그인, 계정 동기화
- 부모·아이 계정 연결
- 친구, 랭킹, 공유
- 랜덤박스, 시즌 이벤트, 일일 퀘스트
- 음식 진화 및 전설 등급
- 칼로리와 영양소 계산

제외 기능은 핵심 게임 흐름이 실제 사용을 유도한다는 증거를 얻은 뒤 검토한다.

## 3. 핵심 사용자 흐름

1. 홈에서 `식사 카드 획득하기`를 누른다.
2. 사진을 촬영하거나 갤러리에서 선택한다.
3. 음식 종류를 하나 선택한다.
4. `맛보기`, `절반`, `거의 다` 중 하나를 선택한다.
5. 카드 뒤집기 연출 후 새 카드를 확인한다.
6. 카드를 도감에 저장하고 홈 또는 도감으로 이동한다.

사용자가 해야 하는 일은 사진 한 장과 두 번의 선택이다.

## 4. 화면 설계

### 홈

- 오늘 획득한 카드
- 마지막 식사 시간
- 발견한 음식 수
- 총 경험치
- 큰 `식사 카드 획득하기` 버튼
- 하단 내비게이션: 홈, 기록, 도감

연속 기록은 보조 정보로만 표시한다. 기록이 끊겼다는 경고나 실패 문구는 사용하지 않는다.

### 식사 기록

- 1단계: 사진 촬영 또는 갤러리 선택
- 2단계: 음식 종류 선택
- 3단계: 식사량 선택

음식 종류는 `라면`, `밥`, `과일`, `빵`, `반찬`, `간식`, `음료`, `기타`로 시작한다. 각 단계는 하나의 질문에만 집중하며, 필요한 값이 없으면 다음 버튼을 비활성화한다.

### 카드 공개

- A안 `두근두근 아케이드` 스타일
- 따뜻한 노랑·주황·코랄 색상
- 카드 뒤집기와 반짝임 연출
- 희귀도, 카드 이름, 한 줄 대사, 획득 경험치 표시
- `도감에 저장`을 명확한 주 버튼으로 제공

### 도감

- 최신 카드 우선 카드 그리드
- 카테고리 필터
- 새 카드 표시
- 카드 상세에서 사진, 날짜, 음식 종류, 식사량, 희귀도, 대사 확인
- 첫 MVP에서는 퍼센트 완성률보다 `발견한 음식 수`를 중심으로 표시

## 5. 카드 생성 규칙

### 희귀도

- `Epic`: 처음 기록한 음식 카테고리
- `Rare`: 기존 카테고리에서 처음 기록한 음식
- `Common`: 이미 기록한 음식

식사량은 희귀도에 영향을 주지 않는다. 적게 먹은 아이가 낮은 등급으로 평가받는 느낌을 방지하기 위함이다.

### 경험치

| 식사량 | 경험치 |
| --- | ---: |
| 맛보기 | 10 |
| 절반 | 20 |
| 거의 다 | 30 |

### 카드 이름과 대사

첫 MVP는 음식 종류별로 준비된 이름과 대사 목록에서 결정적으로 선택한다. 같은 음식도 날짜와 사진이 다르면 별도 카드로 저장한다.

예시:

- 라면: `불꽃 라면` — “후루룩! 오늘의 모험이 뜨거워졌어.”
- 과일: `햇살 과일단` — “상큼한 한입이 오늘의 지도를 밝혔어.”
- 밥: `든든 밥방패` — “작은 한술도 모험가의 힘이 돼.”

## 6. 기술 구조

- React
- TypeScript
- Vite
- 모바일 우선 반응형 CSS
- IndexedDB 기반 로컬 저장소

구조는 다음 책임으로 분리한다.

- `domain`: 카드 희귀도와 경험치 계산
- `data`: IndexedDB 읽기·쓰기
- `features/record`: 사진과 선택 흐름
- `features/reveal`: 카드 공개 연출
- `features/collection`: 도감과 상세
- `features/home`: 오늘의 요약
- `ui`: 공통 버튼, 카드, 하단 내비게이션

화면과 규칙을 분리하여 이후 Flutter 앱에서도 카드 생성 규칙과 데이터 모델을 그대로 옮길 수 있게 한다.

## 7. 데이터 모델

### MealRecord

- `id`
- `imageData` (`string | null`; 저장 공간 부족 시 카드 정보만 보존)
- `foodType`
- `amount`
- `recordedAt`

### FoodCard

- `id`
- `mealId`
- `name`
- `rarity`
- `quote`
- `xp`
- `isNew`
- `createdAt`

### Player

- `totalXp`
- `lastMealAt`
- `streak`

Collection은 별도 중복 데이터 대신 저장된 FoodCard와 MealRecord를 조합해 계산한다.

## 8. 오류 처리

- 카메라 권한 거부 시 갤러리 선택을 계속 제공한다.
- 촬영 취소 시 이전 단계로 안전하게 복귀한다.
- 사진이나 필수 선택값이 없으면 다음 단계로 진행하지 않는다.
- 저장 실패 시 오류를 알리고 재시도 버튼을 제공한다.
- 이미지 저장 공간이 부족하면 사진을 제외하고 카드 정보만 저장할지 사용자에게 묻는다.
- 중복 사진은 허용하되 도감 상세에 동일 이미지 가능성을 표시하지 않는다. 중복 판별은 MVP 이후로 미룬다.

## 9. 테스트

### 규칙 단위 테스트

- 새로운 카테고리는 Epic을 반환한다.
- 기존 카테고리의 새로운 음식은 Rare를 반환한다.
- 이미 기록한 음식은 Common을 반환한다.
- 식사량별 경험치가 10, 20, 30으로 계산된다.
- 식사량이 희귀도에 영향을 주지 않는다.

### 사용자 흐름 테스트

- 사진 없이 다음 단계로 갈 수 없다.
- 각 선택 단계에서 뒤로 이동해도 입력이 유지된다.
- 카드 저장 후 홈 요약과 도감이 즉시 갱신된다.
- 새로고침 후 저장한 카드가 유지된다.
- `맛보기`를 선택해도 긍정적인 카드가 생성된다.
- 모바일 너비에서 주요 버튼과 하단 내비게이션이 겹치지 않는다.

## 10. Flutter 전환 기준

웹 MVP를 실제 아이가 최소 7일 사용한 뒤 다음 기준을 확인한다.

- 7일 중 4일 이상 자발적으로 기록
- 기록 완료 중 중도 이탈이 드묾
- 카드 공개 또는 도감을 다시 열어봄
- 사진 촬영과 두 번의 선택을 귀찮아하지 않음

기준을 충족하면 실제 AI 음식 인식과 수정 기능을 웹에서 먼저 추가하거나 Flutter 전환을 시작한다. 기준을 충족하지 못하면 기능을 늘리기보다 촬영 흐름과 카드 보상을 먼저 개선한다.
