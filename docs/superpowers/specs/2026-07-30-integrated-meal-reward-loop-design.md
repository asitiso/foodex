# Foodex 통합 식사 보상 루프 설계

## 목표

AI 기능을 사용하지 않고 기존 음식 카탈로그, 식사 기록, 카드, 미션, 업적, 캐릭터 성장 데이터를 하나의 루프로 연결한다.

`식사 기록 → 통합 보상 → 다음 목표`가 화면 이동 없이 자연스럽게 이어져야 한다. 사용자는 보상 결과를 확인하기 위해 홈, 도감, 모험 화면을 각각 방문할 필요가 없어야 한다.

## 범위

### 포함

- 사진과 음식 선택을 통한 기존 식사 기록
- 시간대 및 음식 태그 판정
- 카드 생성과 희귀도 판정
- 직업 보너스와 콤보 적용
- 일일 미션, 연속 기록, 던전, 보스, 업적 갱신
- XP, 코인, 카드, 장식 보상의 통합 결과
- 캐릭터 성장 및 변신 조건 판정
- 결과 저장 후 보상 연출
- 한 개의 명확한 다음 목표 추천
- 오프라인 저장 및 온라인 복귀 후 동기화
- 동일 기록에 대한 보상 중복 지급 방지

### 제외

- AI 음식 이미지 인식
- 생성형 AI 카드 설명, 뉴스, 영상, 대화
- 새로운 Supabase 테이블 또는 기존 스키마 변경
- 결제, 광고, 소셜 기능

## 핵심 흐름

1. 사용자가 사진, 음식, 섭취량을 선택한다.
2. 기록 ID와 저장 시각을 생성한다.
3. 기존 카탈로그로 음식 태그와 아침·점심·저녁·간식 시간대를 판정한다.
4. 선택한 직업 효과와 당일 태그 조합을 적용한다.
5. 카드 희귀도, XP, 코인, 콤보, 던전 피해량을 한 번 계산한다.
6. 기록 전후 진행 상태를 비교해 새 미션, 업적, 성장, 변신, 지역, 세트 보상만 추출한다.
7. 식사·카드·신규 보상을 하나의 저장 작업으로 처리한다.
8. 저장 성공 후 카드와 통합 보상 장면을 표시한다.
9. 홈, 도감, 모험 상태를 새 기록 기준으로 갱신한다.
10. 사용자에게 다음 행동 한 개를 표시한다.

저장에 실패하면 성공 연출을 표시하지 않는다. 사용자는 같은 기록을 재시도할 수 있으며 기록 ID 기준으로 보상이 중복 생성되지 않아야 한다.

## 통합 보상 결과

한 번의 식사 기록은 다음 결과 객체를 생성한다.

- 기록한 시간대와 음식 태그
- 생성된 카드와 희귀도
- 기본 XP와 직업·콤보 추가 XP
- 획득 코인
- 완료한 일일 미션
- 연속 기록 변경
- 클리어한 던전 방과 보스 피해량
- 해금한 업적
- 캐릭터 성장·변신 여부
- 새 지역, 세트, 장식 보상
- 다음 목표

화면에는 모든 항목을 동시에 노출하지 않는다. 카드 획득을 먼저 보여주고, 핵심 보상 최대 세 개와 다음 목표 한 개를 표시한다. 상세 결과는 접힌 영역에서 확인한다.

## 다음 목표 선정 우선순위

1. 아직 완료하지 않은 오늘의 아침·점심·저녁 방
2. 한 번의 기록으로 달성 가능한 일일 미션
3. 다음 성장까지 가장 가까운 캐릭터 목표
4. 한 장 남은 세트 또는 앨범 분류
5. 주간 원정 목표

동시에 여러 목표를 나열하지 않고 가장 가까운 목표 하나만 추천한다.

## 보상 중복 방지

- 식사 기록 ID를 보상 계산의 기준 키로 사용한다.
- 저장된 카드의 mealId가 이미 존재하면 새 보상을 생성하지 않는다.
- 보상 키는 `보상종류:보상ID` 형식을 유지한다.
- 로컬과 Supabase가 같은 보상을 포함할 경우 한 번만 합친다.
- 연출을 건너뛰거나 앱을 닫아도 저장 상태는 유지한다.
- 저장 완료 전에는 도감·업적·코인을 성공 상태로 표시하지 않는다.

## 화면 설계

### 기록 화면

사진, 음식, 보상 준비의 세 단계만 보여준다. 단계별 주 행동은 하나이며 기존 디자인 토큰을 사용한다.

### 보상 화면

카드 획득 장면을 먼저 표시한다. 이후 XP·코인·새 해금 중 중요한 세 항목만 보여준다. 연출은 탭으로 건너뛸 수 있고 모션 감소 설정에서는 즉시 결과로 전환한다.

### 홈 화면

새 기록에 반응한 캐릭터와 다음 목표를 먼저 보여준다. 세부 통계는 기존 하단 영역에 유지한다.

### 도감과 모험

새로 채워진 앨범 슬롯과 완료한 미션·업적에 NEW 표시를 남긴다. 새 섹션을 추가하지 않고 기존 앨범·성장·오늘·업적 탭 안에서 처리한다.

## 오류 및 오프라인 처리

- 기록 준비 실패: 사용자가 입력한 초안을 유지하고 다시 카드 생성 버튼을 제공한다.
- 용량 초과: 사진 없이 저장하는 기존 복구 경로를 유지한다.
- 네트워크 실패: 로컬에 저장하고 동기화 대기 상태를 표시한다.
- 동기화 재시도: 기록 ID와 보상 키로 중복을 제거한다.
- 과거 새로고침 응답: 최신 상태를 덮어쓰지 않도록 기존 요청 순서 보호를 유지한다.

## 디자인 제약

- 새 기능을 위해 홈이나 도감에 상태 카드를 추가하지 않는다.
- 화면마다 강조 버튼은 하나만 둔다.
- 크림, 보라, 노랑의 기존 팔레트와 동일한 모서리·그림자를 사용한다.
- 결과 항목이 네 개 이상이면 상세 영역으로 접는다.
- 모바일 320px에서 가로 스크롤과 하단 내비게이션 겹침이 없어야 한다.
- prefers-reduced-motion에서 이동·흔들림·파티클을 제거한다.

## 테스트 기준

- 동일 기록을 두 번 저장해도 보상이 한 번만 생성된다.
- 직업과 태그 조합에 따라 XP가 정확히 달라진다.
- 하루 시간대별 던전 방이 중복 클리어되지 않는다.
- 기록 전후의 신규 업적과 성장만 결과에 포함된다.
- 저장 실패 시 성공 연출과 다음 목표가 표시되지 않는다.
- 오프라인 저장 후 온라인 복귀 시 중복 없이 동기화된다.
- 보상 연출 건너뛰기와 모션 감소 설정이 동작한다.
- 기존 카드 저장, 도감 필터, 퓨전, 월간 리포트 테스트가 유지된다.

## 완료 조건

- 한 번의 기록으로 모든 관련 진행 상태가 한 번 계산되고 한 번 저장된다.
- 카드, XP, 미션, 던전, 업적, 성장 결과가 동일한 기록을 기준으로 일치한다.
- 보상 화면 이후 다음 행동 하나가 명확하게 제시된다.
- 기존 화면의 정보 밀도와 디자인 일관성을 해치지 않는다.
- 전체 테스트와 프로덕션 빌드가 통과한다.
