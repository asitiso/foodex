# Meal-first Game Loop Design

## Goal

기록한 식사 횟수 자체가 즉시 게임 보상으로 연결되어, 간식 수집보다 실제 식사 행동을 자연스럽게 늘린다.

## Scope

- 하루 식사 게이지: 오늘 기록한 식사 수를 0~3+ 단계로 표시한다.
- 하루 콤보: 1끼, 2끼, 3끼를 각각 보상 단계로 보여준다.
- 다음 한 끼 미션: 아직 달성하지 않은 가장 가까운 식사 목표 하나를 안내한다.
- 성장 보드: 누적 식사 횟수 3/7/14/30/100을 캐릭터 성장 목표로 표시한다.

## Non-goals

- Supabase 스키마 변경
- 음식 이름별 신규 업적 생성
- 칼로리, 체중, 의료적 판단
- 식사를 못 한 날의 연속 기록 초기화

## Architecture

`mealGameLoop.ts`가 기존 `MealRecord` 목록을 받아 순수 함수로 `MealGameLoopState`를 만든다. 홈 화면은 이 상태를 표시하고, 저장·동기화 로직은 기존 흐름을 그대로 사용한다.

## Rules

- 오늘 식사 수는 로컬 날짜 기준으로 센다.
- 게이지 단계는 `min(todayMeals, 3)`이다.
- 콤보는 1/2/3끼 단계이며, 3끼 이상은 3끼 완료로 고정한다.
- 성장 목표는 누적 기록 수 기준이며, 다음 목표와 남은 식사 수를 계산한다.
- 다음 한 끼 미션은 오늘 식사 수가 0이면 1끼, 1이면 2끼, 2 이상이면 3끼 목표를 안내한다.
- 식사 기록이 없는 날에도 기존 데이터는 정상 표시되며 앱을 잠그지 않는다.

## UX

- 홈에 `오늘의 식사 게이지`, `다음 한 끼`, `다음 성장까지 N끼`를 배치한다.
- 완료 단계는 기존 보라색·노란색 팔레트로 강조한다.
- 모션 감소 설정에서는 색상·텍스트 변화만 유지한다.

## Testing

- 오늘 식사 수와 게이지 단계
- 콤보 단계와 다음 한 끼 목표
- 성장 목표 경계값(0, 3, 7, 14, 30, 100)
- 자정 경계와 빈 기록
- 홈 화면 핵심 문구 노출
