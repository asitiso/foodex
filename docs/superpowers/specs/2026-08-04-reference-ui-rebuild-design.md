# Foodex 레퍼런스 UI 재구축 설계

## 목표

`agent/foodex-reference-home-v4` 브랜치에서 현재 임시로 구성된 HUD, 공중에 떠 있는 알약형 버튼, 4칸 하단 메뉴를 제거하고, 제공된 레퍼런스 이미지와 거의 동일한 구조와 시각 위계로 홈 UI를 다시 구축한다.

핵심 목표는 다음과 같다.

- 첫 화면에서 즉시 키즈 게임으로 인식되는 구조
- 상단 상태 정보, 중앙 로고, 월드 인터랙션, 하단 내비게이션이 서로 겹치지 않는 명확한 레이어링
- 기존 데이터와 클릭 콜백은 그대로 유지
- 375×667, 390×844, 430×932에서 한 화면 사용 가능
- 이후 배경·건물·캐릭터 에셋을 교체해도 UI 구조가 흔들리지 않는 구성

## 확정 방향

사용자는 레퍼런스와 거의 동일하게 재현하는 A안을 선택했다.

따라서 이번 작업은 현재 Foodex의 임시 UI 스타일을 부분 보정하는 방식이 아니라, 홈 UI를 역할별 컴포넌트와 전용 스타일로 다시 정리하는 작업이다.

## 유지 범위

다음은 변경하지 않는다.

- `WorldHomeScene`이 받는 데이터 구조
- 레벨, 카드, 식사, 연속 기록, 코인 값
- `onRecord`, `onOpenCollection`, `onOpenAdventure`, `onOpenMeals`, `onOpenCompanion`, `onOpenLevel`, `onOpenCoins` 콜백
- 캐릭터 선택 및 감정 데이터
- 라우팅, 저장소, Supabase, 코인 시스템
- 다른 화면의 UI

## 제거 또는 대체 대상

다음 v4 임시 표현은 새 UI로 대체한다.

- 화면 폭 전체를 감싸는 상단 HUD 패널
- 도감·모험·버디의 동일한 보라색 알약 버튼
- 원형 텍스트 중심 식사 기록 버튼
- `업적 / 퀘스트 / 상점 / 소식` 4칸 하단 도크
- 중복되거나 검은 배경이 남는 임시 이미지 레이어
- 여러 CSS 파일에 분산된 상충 위치 보정

## 화면 구조

레이어 순서는 다음과 같이 고정한다.

1. 하늘과 원경 배경
2. 배경 건물과 식생
3. 랜드마크 건물
4. 캐릭터와 그림자
5. 효과
6. 월드 인터랙션
7. 상단 HUD와 로고
8. 하단 내비게이션

UI 요소는 배경 이미지 일부가 아니라 독립적인 HTML/CSS/SVG 컴포넌트로 유지한다.

## 상단 HUD

### 구조

상단 HUD는 레퍼런스처럼 화면을 덮는 하나의 패널이 아니라 서로 분리된 요소로 구성한다.

- 왼쪽 세로 상태 카드 3개
  - 레벨
  - 카드 수
  - 식사 진행과 연속 일수
- 오른쪽 코인 캡슐
- 중앙 FOODEX 로고

### 상태 카드 규칙

- 크림색 카드 면
- 진보라색 외곽선
- 아래쪽 입체 그림자
- 제목은 작고 진한 남색
- 핵심 숫자는 크게 표시
- 카드 너비는 동일하게 유지
- 식사 카드만 보조 문구로 연속 일수 표시

### 코인 캡슐 규칙

- 금색 코인 아이콘
- 보유량 숫자
- 오른쪽 원형 `+` 버튼
- 보라색 프레임과 금색 하이라이트
- 기존 코인 클릭 콜백 유지

### 로고 규칙

- 화면 중앙 상단
- 흰색 입체 글자
- 보라색 외곽선
- 분홍·보라색 하단 돌출 그림자
- 오른쪽 금색 별
- 상태 카드와 코인 캡슐 사이의 중앙 안전영역을 사용

## 월드 인터랙션 UI

모든 랜드마크 버튼을 같은 형태로 만들지 않는다.

### 도감

- 빨간색 건물 간판형
- 책 또는 도감 아이콘
- 건물 전면에 부착된 것처럼 배치
- 기존 `onOpenCollection` 연결

### 식사 기록

- 파란색 카메라 건물 또는 카메라 오브형
- 홈 화면에서 가장 강한 메인 행동
- 금색 또는 밝은 크림색 외곽 강조
- `식사 기록` 문구와 카메라 아이콘
- 기존 `onRecord` 연결

### 모험

- 성 입구와 연결되는 보라색 간판
- 성을 가리지 않고 입구 또는 계단 부근에 배치
- 기존 `onOpenAdventure` 연결

### 버디

- 청록색 간판형
- 버디 하우스에 부착된 것처럼 배치
- 기존 `onOpenCompanion` 연결

### 공통 규칙

- 최소 터치 영역 52px
- 시각 요소와 클릭 영역 분리 가능
- 눌림 효과는 위치 이동을 깨뜨리지 않도록 내부 면만 이동
- 명확한 키보드 포커스 표시
- 접근성 이름 유지

## 하단 내비게이션

### 구조

레퍼런스처럼 5개 탭으로 구성한다.

1. 홈
2. 도감
3. 촬영
4. 모험
5. 버디룸

현재 홈 화면 내부의 4칸 보조 메뉴는 제거한다.

### 시각 규칙

- 전체 바는 진보라색
- 각 탭은 독립된 둥근 카드 또는 버튼
- 아이콘 위, 텍스트 아래
- 중앙 촬영 탭은 주황색과 금색으로 크게 강조
- 선택된 탭은 금색 테두리와 광택
- 하단 safe-area 대응

### 기능 규칙

- 기존 앱의 실제 하단 내비게이션이 이미 있다면 중복 생성하지 않고 해당 컴포넌트를 재사용하거나 홈 전용 시각 클래스를 적용한다.
- 탭 순서와 콜백은 변경하지 않는다.

## 캐릭터와 효과

- 푸디는 중앙 광장 하단에 배치
- 하단 내비게이션에 가려지지 않음
- 캐릭터 크기는 화면 폭 기준으로 반응형 조정
- 그림자는 캐릭터 발 아래 타원형
- 글로우와 반짝이는 캐릭터 또는 주요 행동을 보조하는 정도로만 사용
- 검은색 또는 어두운 사각 배경이 남는 이미지 에셋은 사용하지 않음
- 투명 에셋이 준비되지 않으면 기존 벡터 캐릭터를 우선 사용

## 컴포넌트 구조

### `ReferenceGameHud`

역할:

- 세로 상태 카드 3개
- 코인 캡슐
- 중앙 로고의 배치 컨테이너

입력:

- 현재 레벨과 진행률
- 카드 수
- 오늘 식사 수와 목표
- 연속 일수
- 코인 잔액
- 기존 열기 콜백

### `ReferenceStatusCard`

역할:

- 레벨, 카드, 식사 상태 카드의 공통 구조
- 제목, 핵심 값, 보조 문구, 진행 바를 선택적으로 표시

### `ReferenceLandmarkButton`

역할:

- 도감, 모험, 버디의 간판형 버튼
- `variant`로 빨강, 보라, 청록 스타일 구분
- 아이콘, 문구, 접근성 레이블, 클릭 콜백 유지

### `ReferenceRecordButton`

역할:

- 식사 기록 전용 메인 행동
- 일반 랜드마크 버튼과 분리해 시각 우선순위 보장

### 하단 내비게이션

가능하면 기존 내비게이션 컴포넌트를 재사용한다. 홈 화면 내부에서 별도 보조 메뉴를 추가하지 않는다.

## CSS 구조

- 새 전용 파일 하나를 마지막에 불러온다.
- 권장 경로: `src/features/home/referenceHomeUi.css`
- 기존 `homeSceneUi.css`, `homeSceneV4.css`의 임시 규칙은 점진적으로 제거하거나 새 파일에서 더 이상 필요하지 않게 정리한다.
- 같은 요소의 위치를 여러 파일에서 중복 선언하지 않는다.
- 주요 좌표는 CSS 사용자 지정 속성으로 한곳에서 관리한다.

예시 변수:

- `--home-hud-top`
- `--home-logo-top`
- `--home-collection-x`
- `--home-record-y`
- `--home-adventure-x`
- `--home-buddy-y`
- `--home-character-bottom`
- `--home-nav-height`

## 반응형 기준

### 375×667

- 상태 카드와 코인 캡슐이 로고와 겹치지 않음
- 하단 내비게이션과 캐릭터가 겹치지 않음
- 모든 랜드마크 버튼이 화면 안에 완전히 보임

### 390×844

- 기본 기준 화면
- 레퍼런스와 가장 유사한 비율
- 캐릭터와 카메라 메인 행동이 중앙 광장 안에 위치

### 430×932

- UI가 지나치게 커지지 않도록 최대 크기 제한
- 배경과 건물의 여백을 활용해 화면이 답답해지지 않음

## 접근성

- 모든 버튼은 기존 `aria-label` 또는 동일한 접근성 이름 유지
- 장식용 이미지는 빈 `alt`와 `aria-hidden="true"`
- 키보드 포커스 링 제공
- 색상만으로 선택 상태를 구분하지 않음
- `prefers-reduced-motion`과 기존 `reducedMotion` 값을 모두 존중

## 테스트

### 컴포넌트 테스트

- 상태 카드 3개가 올바른 값으로 렌더링되는지 확인
- 코인 버튼 클릭 시 기존 콜백 1회 호출
- 도감·모험·버디·식사 기록 버튼이 기존 콜백을 유지하는지 확인
- 하단 메뉴의 기존 4개 보조 항목이 홈 장면에서 제거됐는지 확인
- 기존 접근성 이름 유지 확인

### 회귀 테스트

- `WorldHomeScene`의 기존 기능 테스트 유지
- 레이어 컴포넌트 테스트 유지
- 캐릭터 클릭 반응 유지
- TypeScript 빌드 성공
- Vercel Preview 성공

### 시각 검증

375×667, 390×844, 430×932에서 다음을 확인한다.

- HUD와 로고 비겹침
- 랜드마크와 버튼의 연결감
- 식사 기록 버튼의 시각적 우선순위
- 캐릭터와 하단 내비게이션 비겹침
- 버튼 잘림 없음
- 검은 배경 또는 중복 건물 없음

## 구현 순서

1. 현재 임시 홈 UI 규칙과 컴포넌트 의존성 정리
2. 상단 HUD와 로고 재구축
3. 도감·모험·버디 간판 버튼 재구축
4. 식사 기록 메인 버튼 재구축
5. 홈 내부 4칸 보조 메뉴 제거
6. 기존 하단 내비게이션을 레퍼런스 스타일로 적용
7. 캐릭터·그림자·효과 위치 재조정
8. 반응형 보정
9. 집중 테스트, 전체 테스트, 빌드, Vercel Preview, 모바일 시각 검증

## 비범위

이번 작업에서는 다음을 하지 않는다.

- 새 게임 기능 추가
- 새로운 데이터 모델 또는 API 추가
- Supabase 스키마 변경
- 캐릭터 성장 시스템 변경
- 모든 화면의 전면 리디자인
- 새로운 프리뷰 브랜치 생성
- 완성되지 않은 이미지 에셋을 억지로 사용

## 완료 기준

- 제공된 레퍼런스와 동일한 UI 위계가 느껴짐
- 상단 상태 카드, 코인 캡슐, 로고가 분리되어 보임
- 도감·식사 기록·모험·버디 버튼이 역할별 디자인을 가짐
- 하단 내비게이션이 5탭 게임 UI로 보임
- 기존 기능과 데이터 흐름이 그대로 동작함
- 세 가지 목표 모바일 화면에서 겹침과 잘림이 없음
- 작업은 계속 `agent/foodex-reference-home-v4`에 누적됨
